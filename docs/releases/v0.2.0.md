# NeoGenealogy v0.2.0 — Research Queue + Web UI

## Highlights

Primera interfaz web funcional integrada con el pipeline completo:

- Dashboard con resumen del árbol y Top 5 oportunidades.
- Research Queue priorizada con filtros `priority`, `min_score`, `sort` (score/priority/confidence) y paginación.
- Opportunity Detail con `why`, `what`, `potential_sources` y `ScoreBreakdown` explicable (`+30 Direct ancestor — reason`).
- Persons (paginado), Person Detail (findings + oportunidades), Findings (filtros `severity/type`), Branches (orden `branch_score`), Source Coverage (Birth/Marriage/Death/Other/Overall).
- SQLite persistencia transaccional (WAL, foreign_keys=ON, `analysis_runs`).
- REST API Axum read-only `/api/v1/*` con paginación y OpenAPI.
- Docker single-container `API + web/dist` en `http://localhost:3000/` (mismo origen).

## Research Queue

NeoGenealogy prioriza automáticamente oportunidades usando el motor de scoring existente (0–100). Cada oportunidad expone sin recálculo:

- `score`, `priority` (critical/high/medium/low), `confidence` (0–1), `researchability` (high/medium/low)
- `why` (importancia genealógica), `what` (qué falta), `potential_sources` (Baptism/Marriage/Parish...)
- `breakdown: [{name, points, reason}]` y `total`

Ejemplo `curl http://127.0.0.1:3000/api/v1/trees/1/research-opportunities/top`:

```json
{
  "score": 100, "priority": "critical", "confidence": 0.81, "researchability": "high",
  "why": "Antepasado directo y posible punto de bloqueo",
  "breakdown": { "total": 100, "components": [{"name":"Direct ancestor","points":30,"reason":"..."}] }
}
```

## Architecture

```
GEDCOM → Parser → Analyzer → Scoring → SQLite → Axum API → React Web → Docker
```

Crate layout: `core`, `gedcom`, `analyzer`, `scoring`, `storage`, `api`, `cli`, `web/`

## Docker

```bash
cargo build -p neogenealogy
npm --prefix web run build
docker compose build
docker compose up
# en otra terminal
docker compose exec neogenealogy neogenealogy import test-data/complex.ged --db /data/neogenealogy.db
# abre http://localhost:3000/
```

`Dockerfile` prebuilt copia `target/debug/neogenealogy` + `web/dist` (evita `cargo build` OOM dentro de Docker). `Dockerfile.full` para build completo dentro de Docker.

## Known limitations

- API principalmente read-only (sin POST/PUT/DELETE, sin edición genealógica).
- Sin autenticación, sin colaboración, sin sincronización externa.
- Sin integración FamilySearch / OAuth / scraping / IA / OCR.
- Sin árbol visual genealógico completo (solo tabla/cards de ramas).
- SQLite local (sin PostgreSQL), volumen host `./data`.
- Web sin móvil completo, sin WebSockets/GraphQL.

Próxima fase prevista: edición colaborativa y árbol visual.
